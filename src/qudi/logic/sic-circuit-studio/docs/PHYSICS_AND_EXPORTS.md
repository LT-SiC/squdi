# Gate conventions and their limitations

## Single-spin rotations

`R_a(theta) = exp(-i theta sigma_a / 2)` with `a = x, y`. The editor defaults to `theta = pi/2` and allows `pi` or a custom angle. Whether a gate acts on the central electron or a specific nuclear spin is a **hardware mapping decision not fixed by the generic wires**.

## DDRF

DDRF means dynamical-decoupling radio-frequency control of nuclei conditioned on electronic spin. The abstract *logical* model used in this prototype is:

`U_c,t(a,theta,s) = |0><0|_c ⊗ R_a(s theta)_t + |1><1|_c ⊗ R_a(-s theta)_t`.

Here `s = +1` is `±`, `s=-1` is `∓`; the editor assumes the electron-up state corresponds to `|0>`. This correspondence **must be verified with Erik**: actual SiC V2 levels include a selected spin-3/2 subspace, and their RF pulse sequences can have additional phases, timing, hyperfine effects and nonidealities.

There is a mathematically equivalent logical two-qubit decomposition:
- `a=y`: `CX(c,t); Ry(s theta,t); CX(c,t)`.
- `a=x`: `H(t); CX(c,t); Rz(s theta,t); CX(c,t); H(t)`.

These are *circuit identities* only, not experimentally deployable DDRF pulse programs. The tool never labels such a decomposition as an executable V2 control sequence.

## Time slots

Columns without gates are not exported. Gates in the same column are not assigned hardware timing; the exporter sorts by column and then row. The circuit editor is a logical arrangement, not a calibrated pulse scheduler.

## QASM2 / Qiskit

These outputs are generated by Python standard-library code. Qiskit is a Python SDK, not a new programming language and not the basis of qudi. Qudi is a separate Python/Qt framework for laboratory instrumentation.

## Hardware safety

No Web API for hardware activation is enabled. Before adding one, define authorization, measurement-queue integration, interlocks, and default dry-run behavior with institute staff. Do not publish the existing dummy configuration if it contains credentials.
